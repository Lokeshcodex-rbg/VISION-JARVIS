## 1. Compliance Criteria & 9-Level Verification Taxonomy

STARK AI enforces an evidence-based classification standard. No capability may be promoted to a higher verification level without reproducible proof:

| Verification Level | Strict Definition |
| :--- | :--- |
| **`IMPLEMENTED`** | Source code exists and compiles cleanly on disk. |
| **`UNIT_TESTED`** | Isolated module behavior passed automated unit tests. |
| **`INTEGRATION_TESTED`** | Connected cross-module components passed integration tests. |
| **`LIVE_VERIFIED`** | Real execution was observed, measured, and verified in real time on the host OS. |
| **`SIMULATED`** | Results were produced by deterministic mathematical or physical simulation models. |
| **`PHYSICALLY_TESTED`** | An actual physical device (microphone, webcam, display, OS process handle) was tested. |
| **`EXTERNALLY_VERIFIED`** | Information was verified against identifiable external sources (e.g. ArXiv, DuckDuckGo). |
| **`FALLBACK_OPERATIONAL`** | A documented, tested fallback alternative works when a primary dependency is absent. |
| **`NOT_CONFIGURED`** | An optional dependency, credential, external binary, or hardware device is missing. |
