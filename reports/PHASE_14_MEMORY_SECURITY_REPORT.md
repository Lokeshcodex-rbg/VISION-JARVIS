### 1. THREAT MODEL & SECURITY PRINCIPLES

Personal intelligence systems that retain persistent context across conversations introduce novel security and privacy risks:

1. **Indirect Prompt Injection & Memory Poisoning:** Malicious external content (e.g., webpages, emails, third-party documents) attempting to inject false preferences or override security settings.
2. **Epistemic Privilege Escalation:** Model hypotheses or inferences silently being promoted to authoritative user-confirmed facts.
3. **Cross-Domain Context Leakage:** Sensitive personal communications or credentials leaking into unrelated technical engineering or coding tasks.
4. **Data Residue & Incomplete Deletion:** User deletion requests removing database rows while leaving lingering traces in caches, knowledge graphs, or summaries.
5. **Autonomous Proactive Abuse:** Proactive recommendations executing irreversible or external actions without user knowledge.

### 2. SECURITY MECHANISMS & ARCHITECTURAL DEFENSES

#### 2.1 Untrusted Content Defense (Anti-Poisoning Firewall)

The `MemoryManagementEngine` enforces strict provenance rules for memory creation:

- Content originating from external web scrapes, emails, WhatsApp messages, or third-party APIs is assigned confidence class `UNCERTAIN` and epistemic type `CLAIM`.
- Attempts to ingest untrusted content with `USER_CONFIRMED` or `SOURCE_VERIFIED` confidence are intercepted and downgraded immediately.
- Untrusted content can never alter core system prompts, permission policies, or user avoid lists.

#### 2.2 Epistemic Classification & Immutability

All records in `starkMemoryDb.js` maintain explicit provenance:

- **`USER_CONFIRMED`:** Explicitly articulated by the user via dialogue or verified UI entry.
- **`SOURCE_VERIFIED`:** Derived from deterministic system tests or verified build pipelines.
- **`MODEL_INFERRED`:** Generated by LLM analysis; strictly quarantined from high-trust workflows until confirmed.
- When an inferred fact conflicts with a `USER_CONFIRMED` fact, the system halts with `FLAGGED_UNRESOLVED_CONTRADICTION` and issues a clarification prompt rather than silently overwriting the truth.

#### 2.3 Context Relevance Firewall

The `PersonalContextEngine` provides runtime memory filtering:

- **Task Domain Boundaries:** Filters memories according to active task domain (`ENGINEERING`, `PERSONAL`, `SECURITY`, `SYSTEM`). Engineering tasks are completely shielded from personal messaging history, social context, and personal relationships.
- **Cross-Project Isolation:** Project memories are compartmentalized by unique project IDs (`projectId`). A task executing for Project A cannot retrieve private decisions or milestones belonging to Project B unless explicitly linked in the knowledge graph.

#### 2.4 Avoid Topics Registry

Users can register sensitive terms or subjects in the Avoid Topics registry:

- Normalized regex and token matching intercepts writes containing registered avoid terms.
- Ingestion pipelines abort with `AVOID_TOPIC_VIOLATION`.
- Avoided topics are completely blocked from being surfaced in proactive suggestions or general conversation unless the user explicitly removes the restriction.

#### 2.5 Multi-Location Certified Deletion

When a user requests the deletion of a fact, project, or domain:

1. **Primary SQLite Table:** The record is permanently deleted via parameterized SQL.
2. **In-Memory Cache:** Relevant keys are cleared from active caches.
3. **Personal Knowledge Graph:** The entity node is purged, and all connecting edges are cascade-neutralized.
4. **FTS & Summaries:** Associated full-text indices and summaries are recomputed.
5. **Post-Deletion Verification:** An independent query confirms zero records remain across all stores before issuing a cryptographic deletion receipt.

- *Limitation Disclosure:* Deletion operations guarantee removal from active operational storage. Historical cold-storage backup snapshots created prior to the deletion request remain subject to standard snapshot retention lifecycles and require administrative rotation.

#### 2.6 Least-Privilege Agent Context Projection

Specialist subagents receive strictly partitioned context projections:

- **Coding Specialist:** Technical architecture, language preferences, build artifacts, and code decisions. Personal communications, schedules, and social relationships are stripped.
- **Security Specialist:** Audit logs, permission gates, and authorization policies. User personal preferences are omitted.
- **Personal Assistant:** Communication preferences, schedules, and reminders. Internal system security keys and restricted infrastructure configurations are omitted.

#### 2.7 Level 3 Permission Gating & Emergency Stop

- **`memory_purge_domain`:** Registered in `approvalRequiredTools`. Destructive purges strictly require interactive single-use cryptographic authorization.
- **Emergency Stop Integration:** Engaging Emergency Stop immediately aborts all active memory reads/writes and freezes proactive recommendation processing in $\le 10\text{ ms}$.
