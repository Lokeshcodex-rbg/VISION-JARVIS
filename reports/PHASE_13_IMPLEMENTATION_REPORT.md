## 2. Core Architectural Enhancements

### 2.1 Extended 14-State Task State Machine (`server/dagPlanningEngine.js`)

The task state machine has been unified across all orchestrators to support 14 formal states:

- `CREATED`: Initial task record initialized.
- `UNDERSTANDING`: NLP parsing, domain classification, and parameter extraction.
- `PLANNING`: Dependency-aware DAG generation and topological sorting.
- `READY`: All pre-flight requirements and tool registry validations satisfied.
- `RUNNING`: Active execution of nodes.
- `PAUSED`: Execution paused by user or controller, preserving state.
- `INTERRUPTED`: Transient execution interruption awaiting resumption.
- `BLOCKED`: Dependency or resource block requiring upstream resolution.
- `AWAITING_APPROVAL`: Staged at central permission gateway for user confirmation.
- `VERIFYING`: Independent verification layer inspecting empirical evidence.
- `COMPLETED`: Verified success certified by independent oracle.
- `FAILED`: Fatal unrecoverable error or retries exhausted.
- `CANCELLED`: User or controller aborted with automatic scratch rollback.
- `UNVERIFIED`: Inconclusive or missing empirical evidence (rejects false success).

Transition validation strictly enforces legal forward and backward lifecycle edges in `PERMITTED_STATE_TRANSITIONS`.

### 2.2 Strict Audit Separation of Records (`server/autonomousExecutionEngine.js`)

To prevent the model from confusing planned intent with executed reality, the autonomous engine maintains five independent arrays and records:

1. `userObjective`: Raw, unmutated instruction from user.
2. `plannedActions`: Topological plan generated by DAG planner.
3. `executedActions`: Empirically dispatched tool actions with execution timestamps.
4. `observedResults`: Real outputs, process return codes, and telemetry captured from tools.
5. `verifiedResults`: Verdicts produced by the model-independent `IndependentVerifier`.

### 2.3 Deterministic Idempotency & Zero-Retry Irreversible Safety

- **Action Hashing:** `autonomousExecutionEngineInstance.generateActionId(taskId, nodeId, operation, inputs)` creates deterministic hashes (`act_<sha256_slice>`). If an action ID has already succeeded in `executedActions`, repeated calls are blocked.
- **Irreversible Operations:** Actions such as `send_whatsapp_message`, `confirm_whatsapp_send`, `delete_file`, and financial operations are categorized as irreversible and configured with `maxRetries = 0`. Duplicate dispatches and blind retries are prohibited.

### 2.4 Atomic State Checkpointing & Restart Resumption

- Tasks persist state atomically to `data/tasks/<taskId>_checkpoint.json` using atomic file writes (`fs.writeFileSync` with temp atomic rename semantics).
- On recovery or application restart, `loadCheckpoint(taskId)` restores `completedNodes`, `executedActions`, and execution progress, resuming from the first unexecuted DAG node without repeating already completed steps.

### 2.5 Central Permission Gateway & Cryptographic Token Binding (`server/desktop/permissionGate.js`)

- `PermissionGate.createApprovalToken(tool, args, options)` creates an HMAC-SHA256 signature binding the token to the exact tool name and SHA-256 hash of arguments.
- Tokens expire based on a configurable TTL window (`ttlMs`).
- Any tampering with tool arguments or attempting to use a token for another tool fails validation.

### 2.6 Independent Verification Layer (`server/independentVerifier.js`)

The `IndependentVerifier` guarantees the **Golden Rule of Verification**: *Model claims alone are never accepted as proof of execution success.*
Supported verification methods include:

- `WINDOW_VISIBLE_AND_ACTIVE`: Verifies physical process existence and desktop window active status.
- `MATHEMATICAL_CALCULATION_VERIFIED`: Compares engineering outputs against analytical ground truth with configurable tolerance.
- `SPREADSHEET_DATA_VERIFIED`: Validates file existence, non-empty byte count, row counts for CSVs, and OpenXML AST for Excel workbooks.
- `DOCUMENT_AST_VERIFIED`: Inspects Word (`.docx`) OpenXML AST structure, verifying section headings and content.
- `CODE_EXECUTION_VERIFIED`: Executes scripts in isolated subprocesses, verifying exit code 0 and stdout substring matching.
- `COMMUNICATION_DISPATCH_VERIFIED`: Verifies recipient match, message content, and approved dispatch status.
- `FILE_CONTENT_MATCH` / `FILE_EXISTS_AND_NONEMPTY`: Detects missing artifacts and returns `VERIFICATION_STATUS.UNVERIFIED`.

### 2.7 WhatsApp Desktop Automator Hardening (`server/desktop/whatsapp_automator.py`)

1. **Interactive Desktop Station Attachment:**
   Calls `OpenWindowStationW("WinSta0")` and `OpenDesktopW("Default")`, attaching background Node.js child processes to the active user desktop session.
2. **Window Discovery & Restore:**
   Locates WhatsApp Desktop (`WinUIDesktopWin32WindowClass`) even when minimized (`IsIconic(hwnd) == 1`) without filtering out `IsWindowVisible == 0`. Calls `ShowWindow(SW_RESTORE)` to bring WhatsApp forward.
3. **Resolution-Independent Navigation:**
   Eliminates screen-coordinate mouse clicks for searching contacts. Uses native `Ctrl+F` to focus the search box, pastes the contact name via the Windows clipboard, waits 0.8s for filter results, and taps `Down Arrow` + `Enter` to open the conversation.
4. **Guaranteed Dispatch:**
   In `dispatch_staged_message()`, clicks safely inside the composer at `(rect.left + w * 0.65, rect.top + h * 0.88)`—safely above the Windows 11 Taskbar—to ensure keyboard focus, followed by native `VK_RETURN` key dispatch.

All agents are barred from self-approving elevated permissions, and external untrusted prompts are filtered for prompt injection before processing.

## 4. Emergency Stop Integration

The Phase 13 autonomous execution engine integrates directly with `server/emergencyStopController.js`:

- Engaging Emergency Stop immediately aborts active DAG runs, halts child processes, purges all pending WhatsApp drafts and approval tokens, and latches into `EMERGENCY_STOP_ACTIVE`.
- Resuming a task while Emergency Stop is engaged is strictly rejected.
- Only an explicit `emergencyStopControllerInstance.reset()` returns the system to `STANDBY`.
